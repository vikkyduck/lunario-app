# Персональная память Лунарио

Node/SQLite хранит исходные данные и зашифрованные фрагменты. Python CPU-сервис считает E5-эмбеддинги; отдельный Chroma хранит только векторы, непрозрачные ID и namespace. Индекс перестраиваемый. API сервиса доступен только на localhost с внутренним секретом. Все пользовательские запросы проходят авторизацию Node; user_id из тела запроса не принимается.

## Демо из ТЗ

Python 3.10+; `pip install -r requirements.txt`, затем `python rag.py`.
Демо создает `data/company_rules.txt`, индексирует txt/md в `chroma_db/`, задает 2 вопроса. Для генерации нужны переменные `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, опционально `YANDEX_MODEL` (по умолчанию aliceai-llm-flash). Без ключа явно сообщает, что генерация не проверена. Демо никогда не читает личную базу приложения.

## Рабочий сервис

- Установить CPU PyTorch в отдельный venv, затем requirements.txt. Версии закреплены после проверки.
- Сначала загрузить модель intfloat/multilingual-e5-small в HF_HOME. Рабочий процесс запускается с HF_HUB_OFFLINE=1: загрузка страниц не зависит от Hugging Face.
- После установки runtime, модели и service.env запустить `bash backend/rag/install-service.sh`. Деплой вызывает его автоматически. Он устанавливает 2 unit-файла и отдельную копию Python-кода root:lunario-rag. Отдельный пользователь lunario-rag не читает ключ шифрования дневника.
- В /opt/lunario-rag/service.env: RAG_URL=http://127.0.0.1:5034, RAG_SERVICE_TOKEN=<случайный секрет минимум 32 символа>, RAG_MODEL=intfloat/multilingual-e5-small. Не добавлять файл в git.
- Передать тот же env-файл Node через systemd drop-in. Индексация работает и без ключа генератора. Разговор показывается после сохранения ключа Яндекса и успешного ответа /health.
- Хранение ключа генератора: существующий кабинет → Провайдеры ИИ → Алиса / YandexGPT. Поля API-ключ, folder ID, модель aliceai-llm-flash. Кнопка «Проверить» отправляет короткий запрос без личных данных.

## Обновления и удаление

users.data_rev — долговечный маркер изменений, записывается транзакционно с данными. Фоновая сверка каждые 10 секунд; измененные фрагменты определяются по хешу. Старые записи индексируются полностью. Исходники не читаются из ограниченного окна knowledge.recent.
Удаление rag_state создает транзакционное задание rag_purges. Python хранит tombstone namespace перед удалением; поздняя индексация не может воскресить namespace. Перед генерацией и после нее проверяются владелец, ревизия, namespace, версия контента. Ошибка или смена данных дает «Пока не готовы ответить».
Смена модели требует новой коллекции и RAG_MODEL в обоих процессах. При изменении правил подготовки фрагментов повысить rag-v1 в backend/rag.mjs. Индекс можно восстановить из SQLite, но tombstone-базу сохранять при восстановлении индекса. Восстановление резервной копии должно повторить удаления, сделанные после ее даты; не возвращать старые персональные данные без сверки.

## Контекст и границы релиза

Источники: анкета, натальная карта и ее точность, все записи дневника и ответы, желания, привычки и отметки, аскезы с заметками, настроения, совместимость, вопросы и расклады, настройки дня, отклики, вопросы из разговора. AI-ответы не превращаются в факты. Фото/аудио не распознаются. Результаты тестов подключаются, когда появится их хранилище: source key = test:<result-id>, kind=test_result, текст содержит название, версию теста, дату, ответы и рассчитанный результат.

Поиск: E5 query/passage prefixes, normalized vectors/cosine + простой лексический сигнал. До 24 кандидатов, до 8 различных источников, 8500 символов контекста, 3 прошлых хода по 500 символов на вопрос/ответ. Порог 0.80 и отступ от лучшего результата не больше 0.05 предварительные, требует калибровки на вопросах Лунарио. Для периода «за неделю», «за месяц» и ISO-дат настроения считаются по полному диапазону SQL. Другие временные формулировки пока не нормализуются.
Лимит: 20 попыток генерации на пользователя за день, 2 параллельных генерации на весь процесс, 900 выходных токенов. Сбой провайдера не блокирует приложение. Ответ JSON проверяется по допустимым ссылкам, но это не доказывает содержательную истинность каждого утверждения: нужен отдельный набор вопросов с проверенными ответами и живой пилот.

Трактовки карты выбираются по реальным положениям планет существующим natalMeanings; в MVP включены в персональные фрагменты. Выделение общей векторной коллекции библиотеки и сравнение E5 с mpnet — дальнейшая оптимизация после замера поиска, не условие изоляции.

## Проверки и откат

`node tools/check-rag.mjs` — изоляция, зашифрованное хранение, история старше 120 дней, правки, идемпотентность, гонки удаления, ссылки, точная фраза отказа. Генератор здесь тестовый, это не проверка качества Алисы.
`python backend/rag/check_service.py` — реальная модель/Chroma, разграничение namespaces, идемпотентная индексация, исправления и tombstones на синтетических данных.
`node tools/check-all.mjs` — общие проверки приложения. Живой тест Алисы выполнять после настройки ключа на синтетическом профиле, отдельно от личных дневников.
Откат: выключить yandex в ai_providers либо убрать RAG_URL из Node env; перезапустить Node. При необходимости вернуть прошлый релиз обычным rollback.sh. Миграции 26–27 добавляют таблицы и очистку при удалении аккаунта; старые данные не меняет. Выключение RAG не удаляет дневник.
