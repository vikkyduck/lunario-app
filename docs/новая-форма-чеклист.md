# Добавляете форму со свободным текстом — три строки, которые нужны всегда

Проверено 17.09.2026: во всех формах на сайте (вход, дневник, желания, привычки, аскезы, обращения
в поддержку, профиль, кабинет) защита от SQL-инъекций и от чужого кода в тексте уже стоит одинаково.
Здесь — правило, по которому это сделано, чтобы новая форма ему не изменила.

## Правило одной фразой

**Текст храним как есть, показываем безопасно.** Не вырезаем `<`, `SELECT` или другие «подозрительные»
куски из того, что вводит человек, — для дневника это испортило бы обычный текст. Вместо этого:
значение в SQL идёт отдельным параметром, а при показе на экране — через экранирование.

## Три строки на новую форму

**1. Сервер: значение в SQL — только через `?`, никогда не через `${…}`**

```js
// правильно — значение отдельным параметром
db.prepare('INSERT INTO journal (user_id, text) VALUES (?, ?)').run(u.id, seal(text))

// НЕЛЬЗЯ — текст склеен в сам запрос
db.prepare(`INSERT INTO journal (user_id, text) VALUES (${u.id}, '${text}')`)
```

Если в SQL-строке подстановка `${…}` — то, что в неё подставляется, обязано быть именем таблицы
или колонки из фиксированного списка в коде (как в `backend/account-data.mjs`, `backend/schema.mjs`),
а не значением, которое ввёл человек.

**2. Сервер: перед сохранением — `clean()` или `cleanText()` из `backend/server.mjs`**

```js
const text = cleanText(b.text, 2000)   // многострочный текст: дневник, обращения
const title = clean(b.title, 300)      // однострочный: заголовок, имя
if (text.length < 3) return json(res, 400, { ok: false, error: 'short' })
```

Это не «вырезание опасного» — только чужие управляющие символы и предел длины. Смысл текста
не меняется.

**3. Клиент: при показе на экране — `esc()` из `site/app.js` (или `site/cabinet.js` в кабинете)**

```js
// правильно
box.innerHTML = `<p>${esc(item.text)}</p>`

// НЕЛЬЗЯ — чужой <script> в дневнике выполнится
box.innerHTML = `<p>${item.text}</p>`
```

`esc()` нужен там, где текст вставляется через `innerHTML`. Если вставляете через
`.textContent = item.text` — экранировать не надо, браузер и так не разберёт текст как разметку.

## Когда `esc()` не нужен

* Текст уходит в `navigator.share()` или в буфer обмена (`shareResText()` в `site/app.js`) —
  это обычный текст, не HTML.
* Текст рисуется на `<canvas>` (открытки) — canvas не выполняет разметку.
* Значение ставится в `.textContent`, `.value` через `form_input`-подобные способы, а не в `innerHTML`.

## Проверить, что не забыли

```bash
# сервер: все SQL со свободной подстановкой ${…} — на 17.09.2026 таких 14, и в каждой строке
# подставляется имя таблицы или колонки из константы в коде, а не значение из формы. Новая строка
# в этом списке — повод проверить вручную, что там не текст, введённый человеком.
grep -rn '\.prepare(`[^`]*\${' backend --include="*.mjs"

# клиент: все подстановки .text/.title/.note/.body в шаблонах — рядом обязан быть esc(.
grep -n '\${\(.*\)\.\(text\|title\|note\|body\|subject\)' site/app.js site/cabinet.js
```

Второй барьер уже стоит независимо от этих трёх правил: заголовок
`Content-Security-Policy: script-src 'self'` (`backend/http/headers.mjs`) не даёт выполниться
чужому `<script>`, даже если `esc()` где-то забудут. Но полагаться только на него не стоит —
без экранирования чужой текст всё равно сломает вид страницы.
