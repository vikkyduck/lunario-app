# ТЗ · Ритм дня и конструктор инструментов

Раздел 23 к ТЗ Лунарио · черновик архитектуры 16.09.2026 · **не реализовано, на согласовании**

---

## 23.0 Коротко

Лунарио перестаёт быть каталогом функций и получает **ритм из трёх моментов**:

| Момент | Что делает Лунарио | Что делает человек |
|---|---|---|
| **Утро** · пуш ~09:00 | «На что обратить внимание сегодня»: установка, тема дня, карта — если подключена | читает 20–30 секунд, ничего не обязан |
| **Вечер** · пуш ~21:00 | «Сохранить день»: одно поле + настроение, благодарность, привычки, аскеза | отмечает то, что хочет; день сохранён после любого действия |
| **Воскресенье** · пуш ~13:00 | «Моя неделя»: настроение, что сохранили, что отозвалось, ритм, одна рефлексия | смотрит, сам отмечает, что отозвалось |

А **набор инструментов** человек собирает себе сам: стартовый набор маленький, каталог «Все инструменты» — в один тап из любого раздела. Убрать инструмент — не значит потерять историю.

Формула, к которой всё сводится: *утром Лунарио предлагает тему для наблюдения, вечером помогает сохранить важное, в конце недели возвращает человеку его собственную неделю.*

Принципы из переписки, которые принимаем как правила (они же — критерии приёмки):

1. Вечер — не чек-лист. Нет «3 из 4», процентов, красных пропусков, незакрытого ритуала.
2. Утром — «обратите внимание на…», не «предсказание». Вечером никто не проверяет «точность».
3. В неделе — «что отозвалось», не «что совпало». Связь подтверждает человек, Лунарио не объявляет её за него.
4. Добавление инструмента не включает напоминания. Удаление не стирает записи.
5. Каждый тип данных хранится своим типом: настроение, благодарность, запись, отметка привычки, день аскезы — разные таблицы, как сейчас. Никакой «одной универсальной записи», из которой потом ИИ угадывает.

## 23.1 Что уже есть и переиспользуется

Большая часть ритма в коде есть — разрознённо. Строим не с нуля, а собираем.

| Нужно для ритма | Уже есть | Где |

| Тема дня | лунный день с рекомендацией и темами чтения | `lunar.mjs`, `лунные-дни.txt`, `темы.txt` |

| Настроение (быстрые + 32 оттенка + своё слово) | `moods` | `/api/mood` |
| Благодарность, запись, ответ на вопрос дня | `journal.kind` = `gratitude` / `''` / `answer` | `/api/journal` |
| Привычки на сегодня, отметки | `habits`, `habit_marks`, список «что должно быть сегодня» | `practices.mjs` → `habitList(uid, day)` |

Не хватает трёх вещей: **вечернего экрана** как одного места, **связки утро↔вечер** для недели и **видимости инструментов** по выбору человека. Плюс три ритмичных напоминания вместо восьми поштучных.

## 23.2 Конструктор инструментов («Мои инструменты»)

### Модель

Инструмент = функция из реестра `FEATURES` с ключом (`card`, `gratitude`, `natal`, …). Ключи не меняются — на них уже завязаны напоминания, события и «Новое в приложении».

- `users.preferences.tools` — JSON-массив ключей **видимых** инструментов. Отсутствует → стартовый набор. Не шифруется (настройка, как тема).
- Инструмент либо **служебный** (профиль, настройки, напоминания, данные, поддержка — не отключается), либо **выбираемый**.
- Видимость — только видимость. Таблицы, маршруты, напоминания и история не трогаются. Вернул инструмент — записи на месте.
- Напоминание к инструменту **не включается само** при добавлении; в карточке каталога — ссылка «Напоминание →» в «Уведомления».
- Ничего не грузится по модулям: код всех инструментов уже на устройстве, каталог управляет `hidden` у плиток по `data-feature`. Это реализуется на существующей разметке за один вечер и не требует новой сборки.

### Стартовый набор

Разделы — те, что есть сейчас (Сегодня · Свериться с собой · Дневник · Обо мне):

| Раздел | На старте | В каталоге |
|---|---|---|
| Сегодня | Установка и тема дня (лунный день) — это и есть «утро» | Карта дня, прогноз дня, настроение, привычки, аскезы, «На небе» |
| Свериться с собой | Одна карта с описанием («Разобрать вопрос» с одной картой) | «Да / Нет», руны, расклады Таро |
| Дневник | Свободная запись — это и есть «вечер» | Благодарности, желания, история настроений, итоги недели (всегда, если включён ритм) |
| Обо мне | Профиль | Натальная карта, личный год, нумерология, совместимость, тесты |

«Обо мне» и «Аккаунт» — служебные, обязательной практики там нет. Если человек убрал из раздела всё выбираемое — остаётся спокойная ссылка «Выбрать инструменты», без пустых плиток и без призывов.

Стартовый набор — гипотеза, проверяется на людях; менять его — одна строка в `content/инструменты.txt`, без выпуска кода.

### Каталог

Одна панель `w-tools` («Все инструменты»), открывается из ссылки «Выбрать инструменты» под последней плиткой каждого раздела и из Аккаунт → Приложение → «Мои инструменты». Внутри — группы по разделам, в каждой карточки:

```
Дневник благодарности                                   [Добавлено ✓]
Сохраняйте, кому и за что вы благодарны,
и возвращайтесь к своим записям.
Посмотреть пример · Убрать
```

- Слово «Добавить», не «Подключить» (второе читается как платная услуга).
- «Посмотреть пример» открывает сам инструмент в режиме просмотра (тот же виджет, без сохранения) — отдельных демо-экранов не рисуем.
- Тексты карточек — в контенте, `content/инструменты.txt`: `ключ | раздел | название | описание | в стартовом наборе (да/нет)`. Каталог собирается из этого файла + реестра; новый инструмент появляется в каталоге строкой, на экран человека — по его выбору.
- Стоимость: пока платных инструментов нет — поля нет. Появятся — в той же строке контента `бесплатно / в подписке`, и карточка показывает это **до** нажатия «Добавить».

### Что становится с «Моим ритуалом»

Сейчас на главной живёт «Мой ритуал» — три выбранные практики и кнопка «Продолжить мой день» с «0 из 3 практик». Это ровно то, чего ритм избегает (счётчик). «Ритуал» **растворяется в ритме**: утро показывает своё, вечер — своё, а набор практик — это и есть инструменты. `preferences.ritual` остаётся в базе для совместимости и один раз превращается в `tools` при первом входе после выпуска (миграция на клиенте: `tools = стартовый набор ∪ ritual`).

## 23.3 Утро · «На что обратить внимание сегодня»

**Экран.** Верх «Сегодня» уже утренний: установка (`#h-wish`) и «Вопрос дня». Дорабатываем в один блок «Сегодня стоит обратить внимание на…»:

1. Тема дня — одна фраза из лунного дня по выбранным темам чтения (уже считается для пуша «Лунный день»).
2. Установка дня.
3. Карта дня — плитка, если инструмент подключён; не открыта — «Открыть карту».
4. «Сохранить себе» — открытка (уже есть у установки и лунного дня; одна кнопка на блок).

Читается за 20–30 секунд, никаких полей ввода утром. Слово «предсказание» не используем нигде в интерфейсе и в пушах.

**Пуш `morning`.** Одно напоминание вместо трёх утренних (`card`, `lunar`, `sky`): «Сегодня стоит обратить внимание на {тема}» + вторая строка — установка. Deep link `?open=morning` → главная, блок утра. Время своё, по умолчанию 09:00 по часовому поясу человека (`users.tz` уже есть). Текст — `напоминания.txt`, ключ `morning`, подстановки `{тема}`, `{установка}`, `{n}` (лунный день).

Старые утренние напоминания остаются как «тонкая настройка» для тех, кто их включил, но новым не предлагаются.

## 23.4 Вечер · «Сохранить день»

**Экран** — панель `w-evening`, один спокойный экран:

```
Что хочется оставить от этого дня?
[ поле ]                                        ← одно поле, растёт
Настроение   [спокойно] [устала] [радость] [тревога] [благодарность] [всё…]   ← несколько можно
Благодарность  → меняет подсказку поля на «Кому и за что…» (или второе поле, см. вопрос 3)
Привычки      ☐ Прогулка   ☐ Вода   — только те, что должны быть сегодня
Аскеза        Без скроллинга · день 7 из 14   [держусь] [сорвалась]   [заметка]
Вопрос дня    «Что в сегодняшней задаче на самом деле простое?»  → ответ уходит в дневник как сейчас
                                   [ Сохранить день ]
```

- Показываются только подключённые инструменты: нет привычек — нет строки. Ни одна строка не обязательна.
- **Открылся вечером — уже видно, что сохранено:** отметки за сегодня подсвечены, поле пустое или с текстом дня. Никаких «осталось 2».
- После «Сохранить день» — «День сохранён ✦» и тихая строка «Можно дополнить до полуночи». Ничего не отметил — ничего не должен, никаких напоминаний о задолженности.
- Настроение: несколько сразу (как просила владелица) — таблица `moods` уже принимает одно значение на день; расширяем до списка ключей через запятую в том же поле или второй таблицей `mood_marks(user_id, day, mood)` (чище для отчётов). Своё слово — как сейчас `own:…`.

**Данные — разными типами, одним запросом.** `POST /api/evening` принимает `{ text, kind, moods[], habits[], askesis[{id,kept,note}], answer }` и в **одной транзакции** пишет в `journal`, `moods`/`mood_marks`, `habit_marks`, `askesis_days` через уже существующие функции `practices.mjs` и логику `/api/journal`, `/api/mood`. Один запрос нужен ради атомарности и офлайна (один retry), но **не** ради одной таблицы. `GET /api/evening?day=` — состояние дня для предзаполнения. События: `evening_open`, `evening_save` с деталями `mood|text|gratitude|habits|askesis|answer` — без текстов.

**Пуш `evening`.** «Что хочется оставить от этого дня?» — одна строка. Подавляется, если за сегодня уже есть любая вечерняя запись (тот же приём, что у `gratitude` в `notificationFor`). Deep link `?open=evening`. По умолчанию 21:00, своё время — в «Уведомлениях». Заменяет вечерние `mood`, `gratitude`, `habits`, `askesis` для новых; у старых остаются как тонкая настройка.

## 23.5 Воскресенье · «Моя неделя»

**Экран** — виджет `week` перестраивается (маршрут `/api/week` расширяется, адрес прежний):

1. **Настроение недели** — по дням, как в отчёте по настроениям, без оценок.
2. **Что вы сохранили** — 2–3 фрагмента из записей и благодарностей за неделю, дословно, без интерпретации.
3. **Что отозвалось** — пары «утро ↔ вечер»:
   ```
   Понедельник, утром: «Обратите внимание на свои границы»
   Вечером вы записали: «Отказалась брать ещё одну задачу»
   [Отозвалось] [Не связано] [Не уверена]
   ```
   Пара собирается из `daily_sets` + утренней темы дня и вечерней записи того же дня. Отметка — новая таблица `week_echoes(user_id, day, verdict)`; ничего не отмечено — пара просто показана. Лунарио не пишет «совпало».
4. **Ваш ритм** — дни с отметками привычек и аскез точками, без «дисциплины».
5. **Одна рефлексия** — «Что хочется взять с собой в следующую неделю?» → `journal.kind = 'weekly'`, `title` = вопрос. Необязательно.

Умещается в экран; подробности — по нажатию. **Мало данных** (< 3 записей за неделю) — полного отчёта нет: «На этой неделе вы сохранили 2 момента · Посмотреть их вместе». Совсем ничего — «На этой неделе записей не было. Это нормально» и ничего больше.

**Пуш `week`.** Воскресенье 13:00 по умолчанию, время меняется. «Ваша неделя в Лунарио готова» / при малых данных «На этой неделе вы сохранили 2 момента». Без «вы пропустили». Deep link `?open=week`. Заменяет `moodreport` (перекочёвывает в «Настроение недели»).

## 23.6 Данные и миграции

- `users.preferences.tools` — без миграции (JSON внутри существующего поля).
- `mood_marks(user_id, day, mood, PRIMARY KEY(user_id, day, mood))` — миграция 13; `moods.mood` остаётся «главным» настроением дня для старых экранов и отчётов, `mood_marks` — все отмеченные. Либо оставить одно поле со списком через запятую — см. вопрос 4.
- `week_echoes(user_id, day, verdict TEXT, ts)` — миграция 14.
- `journal.kind` получает значение `weekly` — колонка уже текстовая, миграции нет; экспорт и PDF показывают его как «итог недели».
- `reminders.feature` — три новых ключа `morning`, `evening`, `week` в `REMINDER_FEATURES`; старые ключи не удаляются (у людей есть настройки). Единственный перенос: у кого включён `moodreport` — включить `week` с тем же временем и днём.
- Все миграции — идемпотентные, только добавляют (правило `schema.mjs`), откат выпуска безопасен.

## 23.7 Экраны и путь человека

- **Первый вход** после анкеты — один экран «Ритм»: три строки с временем и переключателем (утро 09:00 · вечер 21:00 · воскресенье 13:00) и кнопка «Включить». Это единственное место, где напоминания предлагаются сами; иначе правило 4 нарушается. Пропустил — ничего не включено, приложение работает.
- **Сегодня:** утренний блок сверху; ниже — «Сохранить день» (карточка-вход в вечерний экран, с 17:00 поднимается выше утра); дальше подключённые плитки; внизу «Выбрать инструменты».
- **Дневник:** лента как сейчас; «Моя неделя» — первой плиткой по воскресеньям и понедельникам, дальше — в «Желания и итоги».
- **Свериться с собой, Обо мне:** плитки по выбору + «Выбрать инструменты».
- **Аккаунт → Приложение:** новая строка «Мои инструменты» (каталог) и «Уведомления» с тремя ритмичными первыми, тонкая настройка — под раскрывашкой.
- Пуши ведут ровно на свой экран (`?open=morning|evening|week` через существующий `openTarget()`).

## 23.8 Контент (без выпуска кода)

- `content/инструменты.txt` — карточки каталога и стартовый набор.
- `content/напоминания.txt` — ключи `morning`, `evening`, `week`, `week-мало`, `week-пусто`.
- `content/вопросы-недели.txt` — вопросы для воскресной рефлексии (по кругу, без повторов, как установки).
- Правило про служебные ключи — в `ПРОЧТИ-МЕНЯ.txt`.

## 23.9 Аналитика и кабинет

События: `tools_add`, `tools_remove` (ключ инструмента в деталях), `morning_view`, `evening_open`, `evening_save`, `week_view`, `echo_mark` (`yes|no|unsure`), `rhythm_enable` (какие из трёх). Отчёт продуктолога «Ритм»: доля людей с ≥1 вечерней записью за неделю, с ≥3, доля с включёнными тремя пушами, распределение «отозвалось / не связано / не уверена» — это единственная честная метрика того, попадают ли утренние темы. Никаких текстов в события.

## 23.10 Чего не делаем сейчас

- Платных уровней и покупок отдельных инструментов: сначала ритм и каталог, монетизация — одним понятным уровнем позже, когда ценность подтверждена.
- ИИ-интерпретации недели: неделя показывает факты, связь подтверждает человек. Персональные разборы (раздел 21) остаются отдельным инструментом по запросу.
- Модульной загрузки кода: видимость решает задачу, сборка не нужна.
- Изменения нижней навигации: четыре раздела остаются.

## 23.11 Порядок работ — пять выпусков, каждый самостоятелен

| # | Выпуск | Что входит | Проверка |
|---|---|---|---|

| 2 | **Вечер** | `w-evening`, `GET/POST /api/evening`, `mood_marks`, пуш `evening` с подавлением | один запрос пишет во все таблицы; повторное открытие показывает состояние; нет счётчиков |
| 3 | **Утро** | блок «обратить внимание», пуш `morning`, открытка | пуш ведёт на блок; текст без «предсказаний» |
| 4 | **Неделя** | новый `/api/week`, `week_echoes`, рефлексия `weekly`, пуш `week`, режим «мало данных» | пары утро↔вечер собираются по дням; отметки сохраняются; малые данные — короткий экран |
| 5 | **Ритм при входе** | экран «Ритм» в анкете, «Уведомления» с тремя первыми, отчёт «Ритм» в кабинете | напоминания включаются только явно |

Каждый выпуск — свой коммит, `check-personal-features` зелёный, UI-сценарий в `check-four-sections` дополняется. Оценка по объёму: 1 и 3 — по вечеру, 2 и 4 — по два дня, 5 — день.

## 23.12 Вопросы владелице

1. Стартовый набор из таблицы 23.2 — согласен? Особенно: карта дня **не** на старте (утро = установка + тема).
2. «Мой ритуал» с «0 из 3» убираем совсем, или оставляем как необязательный инструмент для тех, кому нравится считать?
3. Благодарность вечером — то же поле с другой подсказкой (как советовали) или второе поле? Первое проще, второе честнее к данным: тогда запись и благодарность не спорят за одно поле.
4. Несколько настроений за день: отдельная таблица (чище для недели и PDF) или список в существующем поле (без миграции)?
5. Время по умолчанию: 09:00 / 21:00 / вс 13:00 — так?
6. Старые поштучные напоминания (карта, лунный день, привычки…) оставляем как «тонкую настройку» под раскрывашкой или убираем у всех, кроме тех, у кого включены?
7. Первый выпуск — конструктор или вечер? Конструктор виден сразу и меньше по объёму; вечер — сердце ритма и главная ценность.
