# Уведомления о бэклоге в Telegram

Бот отправляет сообщения в 1 настроенный чат: новая задача, фактическая смена статуса (в том числе через редактирование задачи), новая ссылка. Сообщение содержит номер и название задачи, функцию, новый статус или ссылку; кнопка открывает рабочий кабинет. Доступ к кабинету по-прежнему требует входа. Получатели чата видят уведомления по всем функциям — выбирайте внутренний чат команды с соответствующим доступом.

## Подключение

1. Создать бота через @BotFather или использовать существующего.
2. Для личных уведомлений открыть бота и нажать Start; для группы добавить бота в выбранный рабочий чат с правом отправлять сообщения.
3. В серверном окружении службы приложения задать `TELEGRAM_BACKLOG_BOT_TOKEN` и `TELEGRAM_BACKLOG_CHAT_ID`. Токен хранить в защищенном файле окружения сервера, не в репозитории и не в клиентском коде. Chat ID — числовой идентификатор выбранного чата, у группы обычно отрицательный. Его можно получить из Bot API getUpdates после сообщения боту; не публиковать полный ответ с перепиской.
4. Проверить `PUBLIC_BASE` и `BASE_PATH`: из них формируется адрес кабинета. Перезапустить службу после выпуска кода.
5. Создать контрольную задачу, изменить статус, прикрепить ссылку и проверить 3 сообщения в выбранном чате. Локальные тесты используют подмену Telegram и не подтверждают реальную доставку.

Без обеих настроек отправка выключена. События начинают сохраняться после применения миграции 25; существующие задачи не рассылаются автоматически. Если подключить бота позднее, накопленные события будут отправлены в настроенный чат. При смене получателя оставшаяся очередь тоже направляется в новый чат.

## Доставка и диагностика

Событие создается триггером SQLite в одной транзакции с изменением задачи. Откат задачи откатывает уведомление. Повтор прежнего статуса и повтор той же ссылки не создают новых событий. Отправитель работает в 1 процессе HTTP-сервера, не запускать несколько отправителей на одной базе.

Очередь хранится в `backlog_telegram_outbox`. Поля `state`, `attempts`, `next_at`, `last_error` показывают состояние доставки. При сетевой ошибке и ответе 429 или 5xx повтор происходит с паузой; учитывается `retry_after`. Ошибки 400, 401, 403, 404 оставляют событие со статусом `failed`, чтобы неверный токен или недоступный чат не создавали бесконечные запросы. После исправления настроек администратор может вернуть нужные failed-события в pending через SQLite: `UPDATE backlog_telegram_outbox SET state='pending', next_at=0 WHERE state='failed';`.

Отправленные записи удаляются через 30 дней. Pending и failed сохраняются до доставки или ручного решения администратора. Сбой между приемом сообщения Telegram и записью sent может привести к повторному сообщению; Bot API sendMessage не предоставляет ключ идемпотентности. Текст задач и ссылки не пишутся в журнал ошибок, токен не возвращается браузеру. В очереди сохраняются снимки названий и ссылок даже после удаления задачи.

Проверки: `node tools/check-backlog-telegram.mjs`, `node tools/check-isolation.mjs`. Первый тест входит в `tools/check-all.mjs`.

Документация API: https://core.telegram.org/bots/api#sendmessage
